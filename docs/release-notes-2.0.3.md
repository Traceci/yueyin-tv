# 悦音 2.0.3

这一版集中在两件事上：**「随心听」从点到响的整条链路重做**，以及**在线音源导入后的一轮加固**。顺手把应用图标换成了新的珊瑚配色。

---

## 随心听：点一下就该出声

之前点「随心听」有三种不同的糟糕体验：一开始是画面毫无反应、过十几秒播放页才自己蹦出来；修了一版之后变成播放页弹出、歌刚开始放，App 就退回桌面；再修一版，闪退没了，但每次点都要干等一两秒。

三个问题这次一起收掉。

**为什么以前要等十几秒**：这个入口会把随机挑出的 50 首歌一次性交给播放队列，而队列的默认行为是**把 50 首的播放地址全部取完**才返回。在线音源每首都要走一遍脚本再探活，一首约 300 毫秒，50 首就是 15 秒以上。这段时间里播放页不会出现，遥控器按下去也没人应答，等链路终于跑完、主线程空出来，排队着的按键才被处理——所以看起来像「按了别的键才弹出来」。

现在只同步取第一首，其余在后台按顺序补；取曲目、取地址、后台补链全部移到后台线程，界面不再被网络和脚本调用占住。

**为什么会闪退**：为了不让取地址卡住界面，「后台补链」被整段放进了后台线程。但补链的最后一步是修改播放控制器，而播放控制器**只能在主线程碰**——于是抛出「方法在错误线程被调用」，进程直接退出。现在后台线程只负责取地址，拿到之后回主线程再写进队列。

**为什么每次点都要等**：一是补链任务没人管，一次随心听会在后台补几十首，而在线音源只有一个隐藏的取链通道、严格串行，旧任务不取消，下一次点播就得排在它后面；二是首次点还要现拉一次「全部曲目」索引，电视上要 8 到 10 秒。

现在补链任务统一收口，任何一次新的起播都先掐掉旧的补链；首页加载完就提前把「全部曲目」准备好；点「随心听」直接用提前备好的队列，十分钟内重复点不会重新随机、也不会重新取地址。

## 在线音源：拿真实脚本跑出来的一轮修复

拿一份聚合音源脚本在电视和模拟器上把导入、搜索、点播的完整流程跑了一遍，暴露并修掉这些问题：

- **歌曲信息里少了 `source` 字段**——最要命的一处。音源脚本内部大量接口靠这个字段判断平台，拿不到就抛「不支持的平台」。实测同一首 QQ 歌：不带 `source` 时五组接口全部失败、耗时 9.5 秒；补上之后 0.9 秒拿到地址。QQ 与咪咕整条链路都是被这一处卡住的。
- **第一首取不到就静默跳歌**：取地址失败时那一项的地址是空的，播放器把它当坏源跳过，用户看到的是「点了随心听，歌自己跳走了」。现在同步取前两首，并把第一个拿到地址的提到队首。
- **取地址超时 35 秒太长**：版权受限的曲目会让脚本把五组接口全试一遍（实测 18 秒），取链通道又是串行的，后面的歌全被堵住。收到 12 秒，单首总预算 9 秒。
- **一个平台整体失效会拖死整个队列**：曲库是跨平台混排的，随机 50 首里混着失效平台的歌。现在同一平台连续失败 3 次就熔断 3 分钟，期间直接快速失败。
- **地址探活失败不再降档重试**：返回 404 或一段 JSON 报错，说明这条链路本身就坏了，换个音质也是同一个坏代理，直接换下一个脚本。
- **失败过的脚本自动排后**：导入七八个脚本时总有一半是失效的，以前每次取地址都要先在坏脚本上白等一轮。
- **异步初始化的音源识别不到平台**：少数脚本先做一次版本检查、成功后才宣告就绪，加载完立刻问「支持哪些平台」会拿到空集。现在最多等 2.5 秒。
- **网页上传成功后列表还显示「还没有添加任何文件」**：导入成功会立刻切到「在线音乐」，平台一换整页重绘，这一页的会话状态被清空。列表改为读已保存的音源。
- **点歌排在后台预取后面**：列表加载后会在后台预取 20 首地址，这时用户点歌要排在二十首后面干等。现在主动点播会先取消这一轮预取。
- 取曲 + 取首个地址的一两秒里，随心听卡片标题会变成「随心听 · 准备中…」，不再是点了没动静。

## 应用图标

- 换成珊瑚渐变底（上浅下深）+ 米白实心唱片（珊瑚纹圈 + 珊瑚中心）+ 外圈米白细环，外环右上保留 logo 上那段珊瑚色弧。
- 桌面图标改为自适应图标（矢量的前景 / 背景分层），不再被系统塞进小槽位；电视横幅换成位图，TCL、Google TV 的桌面都能正常取到。
